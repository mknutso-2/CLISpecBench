Ruff check/format and strict Pyright pass for the changed Python code and the
RS274 tests. The native non-Docker/non-model harness suite passes 275 tests;
three Rust backend tests skip because the host lacks Cargo, and 22 Docker or
model-prompting cases are deselected. Rust execution is covered by the Docker
reference matrix. The regrade/scoring subset passes 48 tests, including real
local pytest execution and checks for incomplete reports, pinned images,
historical-result preservation, source preservation, and telemetry directories.
Pyright needed an explicit local `.venv` search path on this machine; no strict
diagnostic rules were disabled to obtain these results.

An independent subagent reviewed the original corpus, test changes, reference
repairs, and regrade workflow and independently judged a preserved Python Low
submission. Review caught and prompted repairs for session-directory handling,
authored files under conventional build-directory names, empty source-directory
preservation, tooling cross-assertions, missing reference parameter validation,
and vacuous negative/trace test passes. Independent prompt/source hash checks
confirmed that model inputs and official submissions remained unchanged.

The following adversarial checks address test quality rather than simply
seeking higher benchmark scores:

- Requiring valid percent framing produced identical per-test outcomes for
  unchanged Astra C++ High and Python Low. A deliberately EOF-strict Python
  Low copy matched ordinary Python Low under the framed suite; its unframed
  counterpart had failed all 35 position cases solely on termination handling.
  Trace assertions use actual physical source lines; outputs are untouched.
- Removing only the output `error` field produces four dedicated schema
  failures and no additional behavioral failures. The detailed schema rule is
  still tested, but no longer repeated as a prerequisite for every rejection.
- A one-line program that always crashes originally earned 186 negative-test
  credits after an overly broad schema-decoupling draft. Requiring a nonempty
  JSON result removed those false rejection credits. Ten further trace tests
  were found to pass vacuously; all ten now reject this mutant. The preexisting
  build/invocation smoke test is the only remaining credit for that valid Python
  script, not an interpreter-behavior credit.
- Removing the probe minimum-distance check, parameter-order check, or required
  parameter checks causes the respective focused tests to fail. Error inputs
  otherwise satisfy the relevant setup requirements.
- The old Python reference fails two of the three new G87 cases: its simplified
  path omits mandated moves and mishandles incremental K. Repaired references
  pass the spec-derived cases. JavaScript/Rust CRC repairs also pass the 73
  combined positive and rejection tests, preserving concave/gouging validation.
- Numeric comparisons accept unit-conversion roundoff but reject a 0.001 error,
  wrong keys, nonnumeric values, and NaN. Tooling cases now own their relevant
  fields; explicitly named integration cases retain combined-state checks.

Some shared prerequisites are fundamental: an implementation must parse a valid
input format and produce observable output before its behavior can be measured.
The suite identifies those gates rather than awarding credit to a crash. The
two TLC/probe cases retain a bounded shared controlled-point prerequisite, with
that dependency documented in their comments. Expectations were not relaxed to
make an incorrect coordinate representation pass.

The historical review checked the v1.0.1 rejection removals/range correction,
v2.0.1 time and rotary-unit fixes, v3.1.0–3.1.6 CRC/G87/G88 clarifications,
v3.1.7 independence cleanup, and v3.1.8–3.1.11 schema/modal/trace rules. Still
valid resolved rules were retained. Incomplete reference parity, fixtures, and
independence work were repaired against those existing rules.

Second-pass work remains separate: the public plain-EOF proposal in
`Evals/RS274/TODO.md`, contradictory implicit-D serialization wording, and a
newly observed reference question about explicit Z commands while TLC is already
active. In the latter experiment, G43 H2 with offset 1.5 followed by G0 Z1 makes
the Python reference report controlled Z=-0.5, while Astra C++ High reports Z=1.
This was not used to alter phase-one expectations. It needs dedicated
specification/coverage review. Adding complete trace engines to the C++ and
JavaScript references is also separate from fixing the scoring tests.
