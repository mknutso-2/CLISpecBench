RS274 v3.2.2 completes the test/scoring-only September 2026 audit. All model-visible
inputs remain byte-identical to the saved Astra runs. This supersedes the
[preliminary v3.2.1 validation](RS274-3.2.1.md); public clarifications are a separate
second pass. The final suite has 555 tests and SHA-256
`3d096665fab1578444b0c0a0f7bfa1975e389a9398a34e265820305b300eca11`.

The prompt hashes in the preliminary report match all 12 archived generations.
Neither `Evals/RS274/prompt/` nor `Evals/_shared/` changed. Source and original
result bytes are preserved and independently hashed by the regrade workflow.
The final score records retain original generation metadata, original scores,
and original token/cost accounting separately from the grading observation.
Regrading makes no model calls.

The initial 12-submission audit was deliberately used to challenge the fixes
before committing final scores. It found 133 failed outcomes, of which 108 came
from five incidental setup or serialization assumptions:

| Shared assumption | Failed outcomes in preliminary cohort | Correction |
|---|---:|---|
| M3/M4 implied rotation despite startup S0 | 66 | Set positive S only where spinning is a precondition; negative tests isolate their intended rejection |
| M6 without any T selection | 20 | Select T0 on the existing M6 lines, preserving M-word count |
| Required default-parameter membership/sparsity | 6 | Observe required G54 startup state; remove the unsupported forced-sparsity test |
| Repeating G20 counted as changing units | 8 | Establish opposite units before enabling CRC |
| G92 offset map had to contain raw G10 values | 8 | Keep required position/modal observations without choosing an unspecified representation |

The final snapshot parameter issue was more serious than its six observed
failures. An independent control changed only the Python reference's final
`parameters` object to `{}`, which the current contract permits. That caused
36 failures under v3.2.1. Under the corrected tests it passes all 555 cases.
Parameter assignments, expressions, G92 and probe writes now use required
position observations; raw parameter values across unit changes and program
end use the explicitly required parameter-file output. Trace initial-state and
changed-parameter checks retain their stronger public contract. The tests do
not silently skip absent values.

Further adversarial checks protect against lost coverage:

- Corrupting persisted parameter values fails all four unit-change/program-end
  persistence checks. Omitting probe parameter writes fails its dedicated case;
  omitting G92.1 parameter clearing fails the translational and rotary cases.
- A valid parameter file with zero header lines and extra comment columns passes
  all seven format/persistence cases. Reversing its data order fails only the
  dedicated format gate; the six relevant-value checks still pass. The format
  gate also retains the exact empty separator, finite values, unique ordered
  indices, valid range and required entries.
- Earlier controls localized missing `error` to four schema cases, avoided the
  35-case EOF cascade, removed crash-derived rejection credit, and made ten
  formerly vacuous trace checks require observable output. These changes remain
  in place. Targeted C++ Max/Python High checks recover twelve spindle failures
  each with no regressions, and JavaScript Low recovers four M6 failures.

Some remaining failures still share a real implementation prerequisite. Five
TLC/control-point cases can arise from one coordinate-frame bug, and should be
read as a cluster rather than five independent defects. There are also focused
zero-duration dwell/modal-delta and probing-guard failures. The regrade report
includes this failure analysis alongside raw counts. Mandatory parsing,
observable output and basic value-reading mechanisms remain prerequisites;
flat pytest totals are not counts of statistically independent capabilities.

This corrected cohort is near the suite's ceiling. Similar results are not
proof of broad RS274 completeness, and one submission per language/effort does
not establish a reliable reasoning-effort ranking. Fair fixture repairs can
raise scores without making the underlying submissions any better.

The public second pass should address plain EOF termination, implicit-D
serialization, raw versus effective G92 offset maps, spindle direction at S0,
and the explicit-Z/TLC interpretation noted in the preliminary report. Complete
C++/JavaScript reference motion-trace engines are a separate substantial feature.
Those existing references' 108 trace failures must remain visible; fixing tests
is not a claim that every reference implements both interfaces.
